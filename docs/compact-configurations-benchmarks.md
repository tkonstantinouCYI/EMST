# Compact configured-plant benchmark results

All inputs are synthetic and generated by `examples/synthetic_configured_fleet.py`. No private Cyprus model or measurements were used.

## Conditions

Python 3.14.8, PuLP 3.3.2, HiGHS 1.16.0 and CPLEX CLI 12.8.0.0 on the same Windows machine. Four requested threads; fresh worker processes; no concurrent agent simulations/tests during timing. Each MIP has a 120-second native limit, zero relative/absolute gap targets and seed zero. Both solvers/formulations use feasibility, dual/optimality and integrality tolerances of 1e-9. No warm starts or transferred solutions/bases; CPLEX uses advance 0 and deterministic parallel mode.

The initial default-tolerance trial is retained in `output/compact-matched-benchmarks/` as diagnostic evidence only. Its forced-transition CPLEX reference solution contained about 0.0001 MW generation in an OFF state and a 0.0002 raw constraint residual. It failed validation. The primary results below rerun both formulations with the same tighter numerical tolerances; physical constraints and gap targets are unchanged. This is not rounding away an infeasible dispatch.

CPLEX repeated presolve is disabled (`repeatpresolve 0`) in both primary variants. With automatic repeated presolve and the same strict tolerances, CPLEX 12.8 claimed a small-reference optimum of EUR13,303.72306, contradicted by HiGHS on the identical LP and by a feasible lifted compact point at EUR12,480.29379. Disabling repeated presolve restored the matching objective. These environment-specific contradictory certificates are retained in `output/compact-strict-benchmarks/` and excluded from primary CPLEX results; no generic solver-bug diagnosis is asserted.

Construction is the initial ISP model build, excluding DAM/input setup and file export. Native solve time includes presolve and search; process/file-loading wall time is retained separately in JSON. HiGHS can overshoot its requested limit while finishing a presolve operation; actual elapsed times are shown.

The LP bound is a separately solved continuous relaxation (before MIP cuts/logical presolve), with its native LP time. Native MIP root observations/bounds and root-relaxation times are also retained in individual JSON/logs. CPLEX first-incumbent times prefixed ~ are console-arrival estimates after the optimization echo and may include buffering; HiGHS uses native callbacks. A dash means unavailable, not zero.

## Correctness and interpretation

The retained reference exactly matches commit aff3574 on the structural parity case: variable bounds/types, objective and all constraint coefficients/RHS/senses are hashed (`output/compact-reference-parity-final/verification.json`). The mathematical mapping and continuous-event integrality proof are in [the formulation note](compact-configurations.md). The final full regression suite passed 171 tests with no skips, failures or errors (`output/compact-final-tests/unit-tests-highs.json`), including 648 independently enumerated state sequences, forced/infeasible paths, bidirectional physical-point lifting, long transition/horizon cases, both RTBM modes, settlement and checkpoint/resume.

The paired daily validation produced identical ISP objectives, DAM, configuration sequences, dispatch, RTBM/settlement prices and participant cashflows in both RTBM modes. Every executed incremental transition cost was counted once. Raw/readable exports and verification are in `output/compact-day-validation/`.

The additional forced three-plant fleet replay passed every stage, physical-security check and participant cash reconciliation in both RTBM modes. Dispatch matched exactly and ISP objective differences were below EUR1e-9. It executes a 13-step cold start across the noon rerun, an inherited start and back-to-back two-/three-GT progression, preserving component clocks and counting EUR11,000 executed transition cost once. Inputs and raw/readable outputs are in `output/compact-fleet-day-validation/`. These explicitly forced paths define a separate validation scenario; they do not replace the unconstrained timing cases.

The long CPLEX optimum has 37 differing plant/MTU state labels: interchangeable GT1/GT2 choices in the two-GT plant and GT2/GT3 choices in the three-GT plant. Both objectives agree within EUR1e-7. The complete physical solutions, including each selected component history, lift in both directions; configurations are not deleted or artificially ordered to remove these alternatives. Initial continuous-relaxation bounds match numerically in every measured case.

Every available benchmark incumbent is checked against the original primal constraints, integer decisions and replayed configuration/component histories. Security slacks are reported separately: an incumbent with diagnostic shortage/surplus is not an unrelaxed security-feasible dispatch. Timed-out incumbents are not passed to settlement.

All 11 directed post-benchmark physical-point lifts passed, including the compact fleet optimum lifted into the reference model with the same objective. Evidence: `output/compact-final-lifts.json`. This establishes feasibility of those points in the other formulation, not global optimality of a time-limited source run. The HiGHS fleet compact incumbent has 470.789 MWh diagnostic energy shortage and 22 MW aggregate reserve shortage; it is not a security-feasible daily simulation.

Certified optimal objectives are compared only when both variants reach zero gap. Time-limited bounds/incumbents are not called matching optima. Different configurations or component permutations at the same certified value are investigated by lifting the complete physical point between formulations; no path/configuration is removed for tie-breaking. Numerical objective comparison uses EUR0.001 tolerance; this is not a solver optimality-gap setting.

Primary aggregate metrics are in `output/compact-final-benchmarks/`. Each run records its evidence directory containing complete inputs, LP/MPS exports, metrics, solutions, native logs, root progress and fingerprints. Primary HiGHS runs are in `output/compact-strict-benchmarks/`; primary CPLEX runs are in `output/compact-cplex-norepeat-benchmarks/`. The scripts regenerate them without private files. The compact model remains opt-in (`configuration_formulation="compact"`); no universal runtime improvement or private-model speedup is claimed.
